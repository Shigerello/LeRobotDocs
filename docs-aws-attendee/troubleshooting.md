# 困ったとき

## うまくいかないとき

| 表示されるメッセージ（一部） | 原因 | 対処 |
| --- | --- | --- |
| `curl: (22) … 403` など（導入スクリプトの取得時） | 導入スクリプトの URL の有効期限が切れた | 講師に新しい URL を依頼する |
| `AWS CLI v2（aws-cli/2.x）が見つかりません` | macOS などで AWS CLI v2 が入っていない | [PC の準備](setup.md) で AWS CLI v2 を入れてから、導入スクリプトをもう一度実行する |
| `unzip コマンドが見つかりません` | Linux で AWS CLI v2 を入れるのに必要な unzip がない | 下の「Linux で unzip を入れる」を実行してから、導入をやり直す |
| `dpkg-deb コマンドが見つかりません` | Session Manager プラグインを入れるのに必要なコマンドがない | [PC の準備](setup.md) の AWS の公式の手順で Session Manager プラグインを入れる |
| `認証情報ファイルに講習会の環境変数がありません` | 指定したファイルが違う（`.credentials` や別のファイルを指定した） | `{{ATTENDEE_ID}}.env` を指定する |
| `共有認証情報ファイルが見つかりません` | `{{ATTENDEE_ID}}.credentials` が `.env` と同じフォルダにない | 2 つのファイルを同じフォルダに置く |
| `… は別の実行環境 …です` または `… は実行環境ではない空でないディレクトリです` | 用意する場所に、別の受講者・別の開催のフォルダやほかのファイルがある | `--dir` で別の場所を指定する |
| `受講者用の環境変数が設定されていません` または `実行環境が設定されていません` | 講習会用の環境を有効にしていない | [環境の有効化](setup.md) の `source …/activate` を実行する |
| `読み込んでいる認証情報 … が実行環境 … と一致しません` | 別の認証情報を読み込んでいる | [環境の有効化](setup.md) の `source …/activate` を実行し直す |
| `（一時認証情報の期限切れの可能性があります）` を含むメッセージ、`サインイントークンを取得できませんでした` | 認証情報の有効期限が切れた | 講師から新しい認証情報ファイルを受け取り、[認証情報の更新](setup.md) で入れ替える |
| `Session Manager プラグインが見つかりません` | Session Manager プラグインが入っていない | [PC の準備](setup.md) で入れる。Linux では導入スクリプトを `--with-ssm-plugin` を付けてもう一度実行してもよい |
| `手元のポート 8443 は既に使われています` | 別の `dcv` を実行中か、ほかのソフトウェアがそのポートを使っている | 実行中の `dcv` を Ctrl+C で止めるか、`--local-port 8444` などを付ける |
| `EC2 インスタンスが起動中ではありません` | 自分の EC2 が停止している | 講師に起動を依頼する |
| `EC2 インスタンスが見つかりません` または `起動中の EC2 インスタンスが複数あります` | 自分の EC2 の準備ができていない | 講師に確認する |
| `接続先のシェルから応答がありませんでした` | 認証情報の有効期限が切れたか、自分の EC2 の準備ができていない | [認証情報の更新](setup.md) で認証情報を入れ替える。直らなければ講師に確認する |
| `接続先で公開鍵を登録できませんでした（… sudo -n -u ubuntu できない可能性があります）` | 自分の EC2 が SSH の接続に対応していない | 表示されたメッセージを講師に伝える |
| `接続先から公開鍵の登録の結果が返りませんでした` または `接続先のホスト鍵を受け取れませんでした` | 自分の EC2 の準備ができていないか、接続が途中で切れた | もう一度実行する。直らなければ、表示されたメッセージを講師に伝える |
| `警告: 接続先の authorized_keys から、この接続のために登録した公開鍵の行（…）を削除できませんでした。` | 接続の終了時の片付けができなかった（認証情報の期限切れなど） | 操作は不要。その行は 10 分以内に使えなくなる。何度も表示される場合は講師に伝える |
| `接続先に git がありません。` | 自分の EC2 に git が入っていない | 講師に確認する |
| `サブモジュール … に、HEAD が指すコミット … がありません。` | 手元のサブモジュールを用意していない | 下の「サブモジュールを用意し直す」を実行してから、Git push をやり直す |
| `接続先の … にブランチ … がありません。` | `git pull` で指定したブランチが自分の EC2 のリポジトリにない | 自分の EC2 のリポジトリにあるブランチ名を `--branch` に指定するか、先に `git push` する |
| DCV のログイン画面でログインできない | パスワードを設定していないか、忘れた | 「DCV のパスワードを設定する」の手順で設定し直す |
| `公開済みの現行版がありません` | 講師が講義資料をまだ公開していない | 講師に確認するか、案内された版を `--version` で指定する |
| `… manifest.json … が現行版の情報 … と一致しません` | 講師が講義資料を切り替えている途中 | しばらく待ってから、もう一度実行する |
| `取得したファイルが manifest.json と一致しません` | 取得の途中でファイルが変わった、または欠けた | もう一度実行する。直らなければ講師に確認する |
| `機器向けの準備（hooks/edge-setup.sh）が失敗しました` | 講義資料に含まれる機器の準備作業が失敗した | 表示されたエラーを講師に伝える |
| `接続先の … が Git リポジトリではない空でないディレクトリです` | 自分の EC2 の同じ名前のフォルダに、リポジトリではないファイルがある | `--remote-dir` で別の場所を指定する |
| `接続先の … に Git リポジトリがありません` | まだ一度も `git push` していない | 先に `git push` する |
| `fast-forward で取り込めませんでした` | 手元と自分の EC2 の両方で別々にコミットした | 手元で `git fetch` とマージなどを行い、履歴をそろえてから実行し直す。分からなければ講師に相談する |
| `ブラウザを開くコマンドが見つかりません` | ブラウザを自動で開けない環境 | 表示された URL をブラウザに貼り付ける |


## 今回の検証で分かったこと

| 症状 | 対処 |
| --- | --- |
| macOS の Git 操作で `unbound variable` | Bash 3.2 / C.UTF-8 と日本語隣接変数に関する修正 `fc6e58d` を含むツールを講師から受け取る。旧配布版は更新未実施だったため、公開済みかを確認する |
| DCV ログイン後が灰色 | デスクトップからログアウトして再ログインする。GNOME に `SIGQUIT` を送らない。改善しなければ講師へ相談する |
| GNOME Terminal の文字が横に広い | 設定でフォントを Monospace 12、セルの幅・高さを 1.00 にする |
| Parquet の `Corrupt footer` | Git LFS ポインタの可能性。[データセットページ](dataset.md)で実体化を確認する |
| S3 バケット一覧が AccessDenied | [S3 バケットパスへの直接 URL](connect.md) を使う。バケット一覧権限は要求しない |

講師に伝えるのは、実行場所（手元 / EC2）、コマンド名、秘密を除いたエラー文です。認証情報ファイルやコンソールのサインイン URL は貼り付けません。

## Linux で unzip を入れる

実行場所: **手元の Linux / Jetson、または Windows の WSL Ubuntu のターミナル**。AWS CLI の導入時に unzip がないと表示された場合に実行します。macOS で実行するコマンドではありません。

```bash
sudo apt install unzip
```

エラーなく終了したら、[導入スクリプトの実行](setup.md)へ戻ってやり直します。今回の実測対象は Mac であり、この Linux 復旧手順は元手順に基づく案内です。

## サブモジュールを用意し直す

実行場所: **手元の PC の、送信する Git リポジトリのフォルダ**。サブモジュールに必要なコミットがないと表示された場合に実行します。

```bash
git submodule update --init
```

エラーなく終了したら、[Git で EC2 へ送る手順](connect.md)へ戻り、Git push をやり直します。
