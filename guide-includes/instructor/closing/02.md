## 2. 不要なバックアップと認証情報を片付ける

以降は講師の運用 dev container 内、`ai-learning-handson-aws-infra` のリポジトリ直下です。[共通設定](<<= guide_link('common.md') =>>) で開催設定ディレクトリを入力します。

`rollout cleanup-snapshots` は、講義中の教材訂正を配る `rollout patch` の前に作った **EBSディスクのスナップショット（バックアップ）** を削除します。

- 開催設定の開催IDに一致し、パッチIDのタグが付いた、自分のAWSアカウントのスナップショットが対象です。パッチIDを省略すると、その開催の全パッチ分が対象になります。
- `--dry-run` は削除せず、スナップショットID・受講者ID・パッチID・作成時刻と予定件数を表示します。
- 対象を絞る場合は `--patch-id <パッチ ID>` や `--attendee {{ATTENDEE_ID}}` を付け、確認と削除の両方で同じ指定を使います。
- 通常の実行では対象一覧と確認が表示され、承認すると削除します。不要と確認できないバックアップは削除しません。

これは学習のチェックポイント、S3の成果ファイル、稼働中のEC2・EBSディスクを削除する処理ではありません。受講者の認証情報の失効は、続く `credentials revoke` が行います。

```bash
uv run gclue-ai-handson rollout cleanup-snapshots \
  --env-dir {{CONFIG_DIR_SH}} --dry-run
uv run gclue-ai-handson credentials revoke \
  --env-dir {{CONFIG_DIR_SH}} --all --dry-run
```

削除対象が今回の開催の不要なバックアップに限られ、全員の回収完了を確認できたら実行します。必要なスナップショットは保管方針を決めてから対象を絞ります。

```bash
uv run gclue-ai-handson rollout cleanup-snapshots \
  --env-dir {{CONFIG_DIR_SH}}
uv run gclue-ai-handson credentials revoke \
  --env-dir {{CONFIG_DIR_SH}} --all
```

削除件数または対象なし、認証情報の失効時刻が表示されることを確認します。失敗があれば成功扱いにせず対象とエラーを構築担当へ伝えます。
