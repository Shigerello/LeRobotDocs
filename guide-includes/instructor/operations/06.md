## 3. 受講者に認証情報を渡す

認証情報には有効期限があり、`--duration-seconds <秒>` で講義の長さに合わせて決めます（例: 8 時間なら `28800`）。

- 指定できるのは 900 秒以上、設定の `max_session_duration_seconds`（最大 43200 秒 = 12 時間）までです。上限を超える値は、注意を表示して上限で発行します。
- 一度渡した認証情報の期限は延ばせません。期限が切れたら、もう一度発行して渡し直します。
- 必ずこの手順のコマンドで発行してください。講師のアカウントで AWS CLI などから直接作ると、AWS の制約（ロールの連鎖）で有効期限が最長 1 時間になり、受講者の接続やファイルの転送が 1 時間で止まります（[アクセス制御の仕様](<<= guide_link('staff/instructor/contracts.md') =>>)）。

`--attendee {{ATTENDEE_ID}}` を付けるとその受講者だけに、付けないと設定ファイルの全受講者に発行します（`--attendee` は複数指定できます）。

### 3.1 受講者の EC2 へ直接書き込む

手元にファイルを残さずに、受講者ごとの EC2 へ書き込みます。
EC2 上の学習ジョブから受講者自身の保存場所へ成果をアップロードするのに必要です。
受講者の EC2 が起動していること、手元に AWS CLI v2 と Session Manager プラグインがあることが必要です。

```bash
uv run gclue-ai-handson credentials send --env-dir {{CONFIG_DIR_SH}} \
  --ec2 --duration-seconds 28800
```

確認: 受講者ごとに `受講者 {{ATTENDEE_ID}} の一時認証情報（有効期限 ...）を <インスタンス ID>（ubuntu） の ... に書き込みました。` と、続けて `source /tmp/gclue-ai-handson-{{EVENT_ID}}-{{ATTENDEE_ID}}.env` の行が表示されれば成功です。

受講者に伝えること: 自分の EC2（ubuntu ユーザー）で次を実行してから使います。

```bash
source /tmp/gclue-ai-handson-{{EVENT_ID}}-{{ATTENDEE_ID}}.env
```

### 3.2 SSH で入れる機器（Jetson など）へ直接書き込む {#ssh-host-check}

講師の PC から、パスワードの入力なしに入れる機器へ 1 名分ずつ書き込みます。最初に **講師の PC のターミナル** で接続を確認します。`<ホスト>` は相手の SSH 接続先へ手動で置き換えます。

```bash
ssh '<ホスト>'
```

対象機器のプロンプトが表示されたら、その機器上で次を実行して講師の PC に戻ります。

```bash
exit
```

講師の PC の運用リポジトリ直下で、認証情報を書き込みます。

```bash
uv run gclue-ai-handson credentials send --env-dir {{CONFIG_DIR_SH}} \
  --ssh-host '<ホスト>' --attendee {{ATTENDEE_ID}} \
  --duration-seconds 28800
```

- `<ホスト>`: ssh の宛先（例: `ubuntu@jetson04.local`、または `~/.ssh/config` の Host 名）
- `{{ATTENDEE_ID}}`: その機器を使う受講者の ID（例: `user04`）

確認: `... を <ホスト> の /tmp/gclue-ai-handson-{{EVENT_ID}}-{{ATTENDEE_ID}}.credentials, /tmp/gclue-ai-handson-{{EVENT_ID}}-{{ATTENDEE_ID}}.env に書き込みました。` と表示されれば成功です。

受講者に伝えること: 受講者の機器で、初めて導入する場合は次を実行します。

```bash
bash bootstrap.sh \
  --env-file /tmp/gclue-ai-handson-{{EVENT_ID}}-{{ATTENDEE_ID}}.env
```

導入済みで認証情報を入れ替える場合は次を実行します。

```bash
gclue-ai-handson-attendee env credentials \
  --env-file /tmp/gclue-ai-handson-{{EVENT_ID}}-{{ATTENDEE_ID}}.env
source ~/gclue-ai-handson/{{EVENT_ID}}/activate
gclue-ai-handson-attendee env info
```

`/tmp` は機器の再起動で消えることがあります。
受講者が導入する（または入れ替える）前に再起動した場合は、もう一度書き込みます。

### 3.3 ファイルに書き出して渡す

受講者ごとのファイルを手元に書き出し、安全な方法で受講者に渡します。最初に、保存先が Git 管理対象外であることを確認します。次のパスが表示された場合だけ発行へ進みます。

```bash
HANDSON_CONFIG_DIR={{CONFIG_DIR_SH}}
git check-ignore "${HANDSON_CONFIG_DIR}/credentials/probe.env"
```

```bash
HANDSON_CONFIG_DIR={{CONFIG_DIR_SH}}
uv run gclue-ai-handson credentials issue \
  --env-dir {{CONFIG_DIR_SH}} --duration-seconds 28800 \
  --output-dir "${HANDSON_CONFIG_DIR}/credentials"
```

確認: `開催 {{EVENT_ID}} の一時認証情報を <人数> 名分発行しました（有効時間 <秒> 秒）。` と、受講者ごとのファイルの場所（上記では `{{CONFIG_DIR}}/credentials/{{ATTENDEE_ID}}.env` と対応する `.credentials`）が表示されれば成功です。

- `.env` と同名の `.credentials` を必ず同じディレクトリにそろえて本人へ渡します。`.env` だけでは導入できません。
- 下記の事前確認で管理対象外と確認してから発行してください。表示されなければ発行を止め、構築担当に保存先の設定を依頼します。
- ファイルには秘密の値が入っています。本人以外に渡らないようにし、渡し終えたら手元のファイルは削除します。
- 書き出し先は `--output-dir <ディレクトリ>` で変えられます。
- Windows の PowerShell で読み込む形式が必要な場合は `--format powershell` を付けます。

受講者には [導入・認証更新のコマンド](<<= guide_link('staff/instructor/support.md') =>>) を案内します。認証ファイルのパスを本人が手動で置き換えます。
