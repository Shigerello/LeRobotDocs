## 1. 始める前の準備

### 1.1 管理者に依頼するもの

次のものを AWS アカウントの管理者に依頼し、そろったら印を付けてください。

- [ ] 構築担当の作業用の権限（構築・撤去に必要な権限の一覧は [アクセス制御の仕様](<<= guide_link('staff/environment/specs/access-control.md') =>>) の「必要な IAM 権限」にあります。`AdministratorAccess` があれば足ります）
- [ ] その権限を使う AWS CLI のプロファイル名（IAM Identity Center を使う場合は、`aws configure sso` で作ったプロファイル）
- [ ] 対象のアカウント・リージョンでの CDK のブートストラップ（1.3 で確かめます）
- [ ] GPU インスタンスの vCPU クォータの引き上げ（1.3 で足りないと分かった場合）
- [ ] AMI が AWS Marketplace の製品の場合は、その製品の購読（利用規約への同意を伴うため、管理者が行います）
- [ ] 2.4 でソフトウェアを導入済みの AMI を新しく作る場合は、AMI を作る権限（一覧は [アクセス制御の仕様](<<= guide_link('staff/environment/specs/access-control.md') =>>) の「管理者の作業」）と、一時的なインスタンスに付けるインスタンスプロファイル（AWS 管理ポリシー `AmazonSSMManagedInstanceCore` を付けたロールのもの）の名前

### 1.2 道具を入れる

次の道具を入れます。
リポジトリの dev container（`.devcontainer/`）を使う場合は、すべて入っているので 1.2 の確認だけ行ってください。

- Python 3.11 以上と [uv](https://docs.astral.sh/uv/)
- AWS CLI v2
- Node.js と AWS CDK の CLI

AWS CDK の CLI を入れます。

```bash
npm install -g aws-cdk
```

入ったことを確かめます。
どれもバージョンが表示されれば成功です。

```bash
uv --version
```

```bash
aws --version
```

```bash
cdk --version
```

リポジトリ直下で、運用ツールと構築用のツールを入れます。

```bash
uv sync
```

`gclue-ai-handson-cdk` の使い方が表示されれば成功です。

```bash
uv run gclue-ai-handson-cdk --help
```

### 1.3 AWS アカウントの状態を確かめる

ここで使うのは、アカウントを変更しない確認のコマンドだけです。
Claude Code を使う場合は、Skill `handson-preflight-check` で同じ確認をまとめて行えます。

[共通設定](<<= guide_link('common.md') =>>) に入力したプロファイルとリージョンを、環境変数に設定します。

```bash
export AWS_PROFILE={{PROFILE_SH}} AWS_REGION={{REGION}}
```

IAM Identity Center を使う場合は、手元の Terminal（インフラリポジトリ直下）で先にログインします。SSO の期限が切れた場合も同じコマンドでログインし直します。
{: #sso-login}

```bash
aws sso login --profile {{PROFILE_SH}}
```

- [ ] **アカウント ID が正しいこと**

  表示された 12 桁の数字が、講習会に使うアカウント ID と同じであることを確かめます。

  ```bash
  aws sts get-caller-identity --query Account --output text
  ```

- [ ] **CDK のブートストラップが済んでいること**

  数字（ブートストラップの版）が表示されれば済んでいます。
  `ParameterNotFound` と表示された場合は、管理者に次の実行を依頼してください。

  ```bash
  cdk bootstrap aws://{{ACCOUNT_ID}}/{{REGION}}
  ```

  ```bash
  aws ssm get-parameter --name /cdk-bootstrap/hnb659fds/version \
    --query Parameter.Value --output text
  ```

- [ ] **GPU インスタンスの vCPU クォータが足りること**

  クォータ（Running On-Demand G and VT instances）の値を表示します。

  ```bash
  aws service-quotas get-service-quota --service-code ec2 \
    --quota-code L-DB2E81BA --query 'Quota.Value' --output text
  ```

  インスタンスタイプ 1 台あたりの vCPU 数を表示します（`g6e.2xlarge` は 8）。

  ```bash
  aws ec2 describe-instance-types --instance-types {{INSTANCE_TYPE}} \
    --query 'InstanceTypes[0].VCpuInfo.DefaultVCpus' --output text
  ```

  すでに動いているインスタンスを表示します。
  G や VT で始まるインスタンスタイプがあれば、その vCPU 数も数に入れます。

  ```bash
  aws ec2 describe-instances \
    --filters Name=instance-state-name,Values=pending,running \
    --query 'Reservations[].Instances[].[InstanceId,InstanceType]' \
    --output text
  ```

  「受講者数 × 1 台あたりの vCPU 数 ＋ すでに動いている G・VT 系の vCPU 数」がクォータ以下であれば足ります。
  足りない場合は、管理者にクォータの引き上げ申請を依頼してください。

- [ ] **VPC をもう 1 つ作れること**

  講習会ごとに専用の VPC を 1 つ作ります。
  1 つ目のコマンドで VPC 数の上限（既定は 5）、2 つ目で今ある VPC の数を表示します。
  今ある数が上限より小さければ足ります。

  ```bash
  aws service-quotas get-service-quota --service-code vpc \
    --quota-code L-F678F1CE --query 'Quota.Value' --output text
  ```

  ```bash
  aws ec2 describe-vpcs --query 'length(Vpcs)' --output text
  ```
