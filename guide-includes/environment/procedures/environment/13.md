## うまくいかないとき

| 症状 | 対処 |
| --- | --- |
| `cdk: command not found` と表示される | 1.2 の `npm install -g aws-cdk` を実行する |
| `Token has expired`、`The SSO session associated with this profile has expired` と表示される | 手元で [1.3 の SSO ログイン](<<= guide_link('staff/environment/procedures/environment.md#sso-login') =>>) を再実行する |
| `is not authorized to perform`、`AccessDenied` と表示される | 表示された操作の権限を管理者に依頼する（一覧は [アクセス制御の仕様](<<= guide_link('staff/environment/specs/access-control.md') =>>)） |
| synth で `availability_zones と max_azs はどちらか一方だけを指定してください` と表示される | 設定ファイルの `max_azs` の行を消す（2.6） |
| synth で `instance.availability_zone は network.availability_zones のいずれかで指定してください` と表示される | `availability_zone` を `availability_zones` に書いたものの中から選ぶ（2.6） |
| synth で `instance.availability_zone ... に含まれません` と表示される | 2.6 の「Availability Zone を指定する場合」のとおり、`availability_zones` にその Availability Zone を加えて書く |
| `/cdk-bootstrap/hnb659fds/version` が見つからないと表示される | 管理者に CDK のブートストラップを依頼する（1.3） |
| deploy が `InsufficientInstanceCapacity` で失敗する | その Availability Zone の在庫が足りない。2.6 で別の Availability Zone を指定して deploy し直す（開催中なら 6.1 の準備が先） |
| deploy が `VcpuLimitExceeded` で失敗する | vCPU クォータが足りない。管理者にクォータの引き上げを依頼する（1.3） |
| deploy が `OptInRequired`、Marketplace の購読についてのエラーで失敗する | 管理者に AMI の製品の購読を依頼する（1.1） |
| deploy・destroy が `disableApiTermination` や終了保護についてのエラーで失敗する | 対象の EC2 の終了保護を外してからやり直す（6.1 の 3、7 の 4） |
| deploy が `already exists` と表示して失敗する（バケット名） | 同じ開催 ID で作ったバケットが残っている。別の開催 ID にするか、中身を確かめてから 7 の 6 でバケットを削除する |
| 初回の deploy が失敗し、スタックの状態が `ROLLBACK_COMPLETE` になった | 7 の 5 の destroy で一度削除し、原因を直してから 4 をやり直す。バケット名のエラーが出たら上の行の対処をする |
| EC2 の起動ディスクの容量が `root_volume_size_gb` にならず、別のディスクが付いている | `root_device_name` が AMI と違う。2.5 で調べ直し、6.1 の準備をしてから deploy し直す |
| 2.4 で一時的なインスタンスの `PingStatus` が `Online` にならない、`start-session` で接続できない | 数分待つ。続く場合は、インスタンスプロファイルに `AmazonSSMManagedInstanceCore` が付いているか、subnet からインターネットに出られるか（パブリック IP が付いているか）を管理者と確かめる |
| deploy が `smaller than snapshot` と表示して失敗する | 2.4 の導入済みの AMI のスナップショットが `root_volume_size_gb` より大きい。`root_volume_size_gb` を 2.4.1 の 2 で表示される大きさ以上にする |
| 5.4 の `start-session` で接続できない | 起動直後は数分待つ。続く場合は、AMI に SSM エージェントが入っているかを確かめる |
| 講師の払出しが `SSM パラメータ ... から読めませんでした` で失敗する | 講師の権限に 5.2 のポリシーがあるか、講師のプロファイルと設定ファイルの開催 ID・リージョンが正しいかを確かめる |
| 受講者の認証情報が 1 時間で切れる | 講師が講師用のコマンドを使わずに作っている。[講師の手順](<<= guide_link('staff/environment/handoff.md') =>>) のコマンドで払い出し直してもらう（5.1 の注意） |
| 受講者を増やしたのに、その受講者の認証情報を作れない | 6.2 の deploy が済んでいるかを確かめる |
