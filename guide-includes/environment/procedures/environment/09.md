## 5. 構築後に行うこと

### 5.1 払出し用の鍵ができたことを確かめる

講師が受講者に認証情報を渡すときは、構築で作られた「払出し専用ユーザー」（人ではない、受講者の認証情報を作るためだけの IAM ユーザー）の鍵を使います。
その鍵は、AWS Systems Manager のパラメータ `/GClueAiHandsOn/{{EVENT_ID}}/IssuerAccessKey` に暗号化して保存されています。
パラメータが 1 件表示されれば成功です（鍵の値は表示されません）。

```bash
aws ssm describe-parameters --parameter-filters \
  Key=Name,Values=/GClueAiHandsOn/{{EVENT_ID}}/IssuerAccessKey \
  --query 'Parameters[].[Name,Type]' --output text
```

`SecureString` と表示されることも確かめます。

> **注意: 受講者の認証情報は、必ず払出し専用ユーザーで作ります**
>
> 講師のロール（IAM Identity Center の権限セットなど）から受講者用のロールを引き受けると「ロールの連鎖」になり、AWS の制約で受講者の認証情報の有効期間が最長 1 時間に制限されます。
> そうなると、受講者の接続やファイルの転送が 1 時間ごとに止まり、講習会を運用できません。
> そのため、受講者用のロールは払出し専用ユーザーからだけ引き受けられるようにしてあります。
> 講師のロールから引き受けられるように権限を変えないでください。

### 5.2 講師に鍵を読む権限を与える

講師が払出しの操作をするには、講師の権限に次の 2 つだけが必要です。
`AdministratorAccess` を持つ講師には、追加の作業は要りません。

- パラメータ `/GClueAiHandsOn/{{EVENT_ID}}/IssuerAccessKey` の `ssm:GetParameter`
- AWS 管理キー `aws/ssm` での `kms:Decrypt`

> **注意**
>
> このパラメータを読める人は、受講者の認証情報を作ることと、講師用の操作（教材の配布など）ができます。
> 必要な講師だけに与え、他の人には与えないでください。

キーの ARN を表示します。

```bash
aws kms describe-key --key-id alias/aws/ssm --query KeyMetadata.Arn \
  --output text
```

講師の権限（IAM Identity Center の権限セットのインラインポリシーなど）に、次のポリシーを加えます。
`{{REGION}}`、`{{ACCOUNT_ID}}`、`{{EVENT_ID}}`、`<キーの ARN>` を置き換えてください。

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "ssm:GetParameter",
      "Resource": "arn:aws:ssm:{{REGION}}:{{ACCOUNT_ID}}:parameter/GClueAiHandsOn/{{EVENT_ID}}/IssuerAccessKey"
    },
    {
      "Effect": "Allow",
      "Action": "kms:Decrypt",
      "Resource": "<キーの ARN>"
    }
  ]
}
```

講師が [講師の手順](<<= guide_link('staff/environment/handoff.md') =>>) の認証情報の払出しを実行し、エラーにならなければ成功です。

### 5.3 講師に設定ファイルを渡す

講師も同じ設定ファイルを使います。
`{{CONFIG_DIR}}/gclue-ai-handson-config.yml` を講師に渡し、講師の作業コピーの同じ場所に置いてもらってください。
講師の PC のプロファイル名が違う場合は、講師が `aws.profile` を自分のプロファイル名に書き換えます。

設定ファイルにはアカウント ID が入るため、Git にコミットしたり、公開の場所に置いたりしないでください。
以降の作業（受講者用ツールの公開、教材の配布、認証情報の払出し）は [講師の手順](<<= guide_link('staff/environment/handoff.md') =>>) で行います。

### 5.4 （任意）インスタンスの中身を確かめる

AMI の条件（2.3）を満たしているかは、インスタンスの中で確かめます。
Session Manager プラグインが入っている PC で、受講者のインスタンスの 1 台に入ります。
`{{INSTANCE_ID}}` は 4 で表示した `i-` で始まる値です。

```bash
aws ssm start-session --target {{INSTANCE_ID}}
```

入れれば、接続の経路（SSM エージェント）は動いています。
受講者が SSH・git で接続する講習会では、中で次を実行します。

```bash
sudo -n -u ubuntu true && echo sudo-ok
ss -ltn 'sport = :22' | grep -q LISTEN && echo sshd-ok
test -f /etc/ssh/ssh_host_ed25519_key.pub && echo hostkey-ok
command -v git flock
```

`sudo-ok`、`sshd-ok`、`hostkey-ok` と、`git` と `flock` の場所の 2 行が表示されれば、SSH・git で接続できます。
`sudo-ok` が表示されない場合は、Session Manager で入ったユーザーから `ubuntu` ユーザーへパスワードなしで切り替えられません。
別の AMI を選ぶか、AMI の sudo の設定を確かめてください。

`exit` で抜けます。
