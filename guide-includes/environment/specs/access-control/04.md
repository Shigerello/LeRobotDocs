## 設計上の判断と理由

| 判断 | 理由 |
| --- | --- |
| 払出しの起点を IAM ユーザーにする | ロールの連鎖による 1 時間の上限を受けずに、最大 12 時間の一時認証情報を発行するため |
| アクセスキーを SecureString のパラメータに置き、講師の権限で読ませる | 講師ごとに長期の認証情報を配らず、読める人を IAM の権限で管理するため。読める人は払出し専用ユーザーの権限を持つことになるため、`ssm:GetParameter` は必要な講師だけに与える |
| アクセスキーをスタックで作り、世代の番号で置き換える | 置き換えを deploy だけで行え、撤去でアクセスキーが確実に消えるようにするため |
| 受講者ロールを 1 つにし、セッションタグで受講者を区別する | 受講者の数だけロールを作らずに、受講者ごとの範囲を IAM の条件で表すため |
| 失効をインラインポリシーで行い、CloudFormation の外で管理する | 発行済みの一時認証情報は STS で取り消せないため、`aws:TokenIssueTime` で拒否する。deploy で消えないよう、スタックはインラインポリシーを定義しない |
| `shared/` の書き込みをバケットポリシーでも拒否する | 受講者ロールの設定の誤りや、他の主体からの書き込みでも教材が変わらないようにするため |
| すべての権限をカスタマー管理ポリシーにする | インラインポリシーを失効の用途だけに空けておくため |
