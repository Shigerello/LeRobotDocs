## 必要な権限を確かめる方法（手順の検証で行う）

手順を検証する開催（試験用の開催など）では、実行者が実際に呼んだ API の操作を CloudTrail のイベント履歴から記録し、「必要な IAM 権限」の表に不足や不要な項目がないかを確かめます。
本番の開催の手順は確定した表に従い、この記録は行いません。

### 仕組みと制約

- CloudTrail のイベント履歴は、管理イベントをリージョンごとに 90 日間、追加の設定と費用なしで保持します。
- S3 のオブジェクトの操作（`s3:GetObject`・`s3:PutObject` など）はデータイベントのため、イベント履歴に含まれません。
- データイベントを記録するには、データイベントを有効にした証跡が必要です。アカウントの変更と費用を伴うため、別に決めない限り対象外とします。
- IAM のイベントは `us-east-1` に、CloudFormation・EC2・SSM・S3 のバケットの操作・KMS・Lambda のイベントはスタックのリージョンに記録されます。
- 構築用 CDK アプリは `CliCredentialsStackSynthesizer` を使うため、CloudFormation がリソースを作成・削除する操作も実行者の主体のイベントとして記録されます。
- イベントは通常 5〜15 分ほど遅れて履歴に現れます。
- `lookup-events` には 1 秒あたり 2 回程度の呼び出しの制限があり、AWS CLI はページの取得を自動で繰り返します。
- 絞り込みの属性 `Username` は、IAM ユーザーではユーザー名、IAM Identity Center などのロールではロールのセッション名（引き受けたロールの ARN の最後の `/` より後ろ）です。

### 記録の手順

作業を始める前に、開始時刻を記録します。

```bash
export TRAIL_START=$(date -u +%Y-%m-%dT%H:%M:%SZ)
```

実行者のセッション名を、表示された ARN の最後の `/` より後ろから確かめます。

```bash
aws sts get-caller-identity --query Arn --output text
```

作業を終えたら 15 分ほど待ち、終了時刻を記録します。

```bash
export TRAIL_END=$(date -u +%Y-%m-%dT%H:%M:%SZ)
```

スタックのリージョンと `us-east-1` のイベントを、作業の名前を付けたファイルに保存します。

```bash
for r in <スタックのリージョン> us-east-1; do
  aws cloudtrail lookup-events --region "$r" --lookup-attributes \
    AttributeKey=Username,AttributeValue=<セッション名> \
    --start-time "$TRAIL_START" --end-time "$TRAIL_END" \
    --output json > cloudtrail-<作業名>-$r.json
done
```

保存したファイルを、`サービス:アクション`、呼び出しの回数、失敗の回数の一覧にまとめます。

```bash
python3 - cloudtrail-<作業名>-*.json <<'PY'
import collections
import json
import sys

counts = collections.Counter()
errors = collections.Counter()
for filename in sys.argv[1:]:
    with open(filename) as source:
        events = json.load(source)["Events"]
    for event in events:
        detail = json.loads(event["CloudTrailEvent"])
        service = detail["eventSource"].split(".")[0]
        action = service + ":" + detail["eventName"]
        counts[action] += 1
        if detail.get("errorCode"):
            errors[action] += 1
for action in sorted(counts):
    print(action, counts[action], errors[action] or "", sep="\t")
PY
```

### 結果の読み方

- `eventSource` の先頭は多くの場合 IAM のアクションの接頭辞と一致しますが、`monitoring`（IAM では `cloudwatch`）のように異なるものがあります。
- `ssmmessages`・`ec2messages` は、Session Manager の接続やエージェントの通信で現れます。
- `sts:GetCallerIdentity` のように、権限なしで呼べる操作も含まれます。
- 失敗の回数があるもの（`errorCode` が `AccessDenied` など）は、不足していた権限を示します。

### 記録の進め方

- 作業（CDK のブートストラップ、deploy、受講者の一時認証情報の発行、一斉配布、destroy など）ごとにファイルを分け、Git の管理対象外の開催の設定のディレクトリ `{{CONFIG_DIR}}/` に保存します。
- 管理者のセッションのほかに、運用ツールが使う主体も同じ方法で記録します。
- 払出し専用ユーザーは、ユーザー名 `GClueAiHandsOn-{{EVENT_ID}}-Issuer` で絞り込みます。
- 講師用ロールのセッション名は `Instructor` です。他の開催と共通の名前のため、イベントの `userIdentity.arn` のロール名で開催を確かめます。
- 受講者ロールのセッション名は受講者 ID です。
- まとめた一覧をこの文書の表と比べ、不足と不要な項目を表に反映します。
- CDK のブートストラップ（スタック `CDKToolkit`）はアカウントとリージョンの単位の作業のため、記録した権限は開催の表とは分けて扱います。
