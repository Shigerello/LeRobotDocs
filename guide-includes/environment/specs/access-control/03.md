## 動作

### 受講者の一時認証情報の発行

`credentials issue` / `send` は、払出し専用ユーザーとして受講者ロールを `sts:AssumeRole` で引き受けます（`commands/credentials.py`（元インフラリポジトリの参照資料））。

- `RoleSessionName` は受講者 ID です。
- セッションタグとして `attendee={{ATTENDEE_ID}}` と `handson-deployment={{EVENT_ID}}` を付けます。
- `DurationSeconds` は `--duration-seconds` の値です。900 未満はエラーにし、`max_session_duration_seconds` を超える値はその上限に切り詰めます。

受講者ロールの信頼ポリシーは次の条件で、払出し専用ユーザーにだけ `sts:AssumeRole` と `sts:TagSession` を許可します。

| 条件 | 内容 |
| --- | --- |
| `aws:RequestTag/handson-deployment` | 開催 ID と一致すること（タグがなければ拒否されるため、付与が必須になる） |
| `aws:RequestTag/attendee` | 設定の `attendees` のいずれかと一致すること（同上） |
| `ForAllValues:StringEquals` `aws:TagKeys` | 付けるタグのキーが `attendee` と `handson-deployment` だけであること |

受講者ロールの権限は、セッションタグを `${aws:PrincipalTag/attendee}` と `${aws:PrincipalTag/handson-deployment}` として参照し、1 つのロールで受講者ごとの範囲を表します。
受講者を加えたときは、信頼ポリシーを更新するために deploy が必要です。

### ロールの連鎖による 1 時間の上限と、その回避

AWS では、ロールの一時認証情報で別のロールを引き受けること（ロールの連鎖）で得たセッションは、最長 1 時間に制限されます。
ロールの最大セッション時間（`max_session_duration_seconds`）はこの場合に効かず、1 時間を超える `DurationSeconds` は拒否されます。

講師は通常、IAM Identity Center の権限セット（実体はロール）で AWS にログインします。
講師の認証情報から受講者ロールを直接引き受けると連鎖になり、受講者の接続やファイルの転送が 1 時間ごとに止まるため、講習会の運用に使えません。

そこで、引き受けの起点を IAM ユーザー（払出し専用ユーザー）の長期のアクセスキーにしています。
IAM ユーザーからの引き受けは連鎖ではないため、受講者ロールと講師用ロールの最大セッション時間（最大 12 時間）まで発行できます。
講師自身の認証情報は、アクセスキーを SSM パラメータから読むことだけに使います（`issuer_session`）。
受講者ロールと講師用ロールの信頼ポリシーは払出し専用ユーザーだけを許可するため、講師のロールから直接引き受けることはできません。

### セッション時間と期限付き URL

| 対象 | 有効期間 |
| --- | --- |
| 受講者ロール・講師用ロールの最大セッション時間 | `max_session_duration_seconds`（3600〜43200、既定 43200） |
| 受講者の一時認証情報 | `--duration-seconds`（900〜最大セッション時間） |
| 運用ツールが使う講師用ロールのセッション | 最大セッション時間（コマンドの実行のたびに引き受ける） |
| 導入スクリプトの期限付き URL（`release bootstrap-url`） | 既定と上限は `max_session_duration_seconds`（`--expires-seconds` で短くできる） |

期限付き URL は講師用ロールのセッションの認証情報で署名します。
署名に使った一時認証情報が切れると URL も使えなくなるため、URL の有効期間の上限を講師用ロールのセッション時間と同じにしています（`commands/release.py`（元インフラリポジトリの参照資料） の `resolve_bootstrap_url_expires`）。
セッションはコマンドの実行時に引き受けるため、URL は作成から最大セッション時間まで使えます。

### 失効

`credentials revoke` は、受講者ロールのインラインポリシー `HandsOnRevokedSessions` に Deny の Statement を書き込みます（`iam:PutRolePolicy`）。

- Statement は `Action: *`、`Resource: *` を拒否し、条件は `aws:PrincipalTag/handson-deployment` が開催 ID と一致し、`aws:TokenIssueTime` が失効時刻より前であることです。
- `--attendee` の場合は、`aws:PrincipalTag/attendee` を条件に加えます。同じ失効時刻の受講者は 1 つの Statement にまとめます。
- `--all` の場合は、受講者の条件を付けません。`--all` の時刻より前の受講者ごとの Statement は不要になるため取り除きます。
- 既存のポリシーを読んで（`iam:GetRolePolicy`）合成するため、失効を重ねても以前の失効は残ります。運用ツールが解釈できない Statement もそのまま残します。
- 失効時刻の後に発行した一時認証情報は使えます。払い出し直すと、失効させた受講者も再び使えるようになります。

このインラインポリシーは CloudFormation の外で管理します。
スタックは受講者ロールにインラインポリシーを定義しないため、スタックの更新では消えません。
ロールはスタックの削除で、このインラインポリシーごと削除されます。

失効の範囲は受講者ロールのセッションだけです。
講師用ロールのセッションと払出し専用ユーザーのアクセスキーは失効の対象外です。
アクセスキーを使えなくするには、`aws.handson_cdk.issuer.access_key_serial` を増やして deploy します（後述）。

### アクセスキーの置き換え

`access_key_serial` を変えると、`AWS::IAM::AccessKey` の `Serial` が変わってアクセスキーが置き換わり、カスタムリソースの更新でパラメータが新しい値で上書きされます。
古いアクセスキーは、CloudFormation の置き換えの後片付けで削除されます。
運用ツールはコマンドの実行のたびにパラメータを読むため、講師の側で行う作業はありません。
古いアクセスキーで発行済みの受講者・講師用ロールの一時認証情報は、有効期限まで使えます。

### S3

講習会用バケットは開催ごとに 1 つです。

| 主体 | `shared/` | `{{ATTENDEE_ID}}/` |
| --- | --- | --- |
| 受講者ロール | 一覧と読み取り | 自分のS3 バケットパスだけ、一覧・読み取り・書き込み・削除 |
| 講師用ロール | 一覧・読み取り・書き込み・削除 | 一覧と読み取り（全受講者） |
| インスタンスロール | 一覧と読み取り | なし |

- 受講者ロールの `s3:ListBucket` は、`s3:prefix` が `shared/`・`shared/*`・`{{ATTENDEE_ID}}/`・`{{ATTENDEE_ID}}/*` のときだけ許可します。
- 受講者ロールは、ガードレールの管理ポリシーで `shared/` への `s3:PutObject`・`s3:DeleteObject`・`s3:PutObjectAcl` を明示的に拒否します。
- バケットポリシーは、講師用ロール（`aws:PrincipalArn`）以外のすべての主体に、`shared/` への `s3:PutObject`・`s3:DeleteObject`・`s3:DeleteObjectVersion`・`s3:PutObjectAcl` を拒否します。管理者の認証情報も対象です。
- バケットポリシーは TLS 以外の要求も拒否します。
- インスタンスロールは、一斉配布の Run Command が `shared/` からファイルを取得するために `shared/` を読みます。受講者のS3 バケットパスへは書けないため、EC2 上のジョブから成果を保存するには、`credentials send --ec2` で EC2 に書き込んだ受講者の一時認証情報を使います。

#### 存在しないキーへの 403

S3 は、要求者がバケットへの `s3:ListBucket` を持たない場合、存在しないキーの `GetObject` に 404 ではなく 403（`AccessDenied`）を返します。
受講者ロールとインスタンスロールの `s3:ListBucket` は `s3:prefix` の条件付きのため、この判定では持たないものとして扱われ、`shared/` の存在しないキーにも 403 が返ります。

受講者用ツールは、現行版の記録 `shared/releases/latest.json` の取得が 404 または 403 で失敗したとき、現行版が未公開であるとみなします（`files.sh`（元インフラリポジトリの参照資料） の `resolve_latest_release`）。
そのため、失効させた一時認証情報での取得も「未公開」と区別できません。
期限切れなど、それ以外のエラーでは止まります。
現行版の扱いは 教材の版と一斉配布の仕様（元インフラリポジトリの参照資料） と 受講者用ツールの仕様（元インフラリポジトリの参照資料） にあります。

### SSM Session Manager

受講者ロールの接続の権限は、次の範囲に限ります（接続経路の仕組みは 接続経路の仕様（元インフラリポジトリの参照資料））。

| 操作 | 範囲 |
| --- | --- |
| `ssm:StartSession`（インスタンス） | インスタンスのタグ `attendee`・`handson-deployment` が、セッションタグの受講者 ID・開催 ID と一致し、セッションタグの開催 ID がこの開催のものであること。`ssm:SessionDocumentAccessCheck` を真にし、使うドキュメントへの権限も確かめさせる |
| `ssm:StartSession`（ドキュメント） | 既定のシェル（`SSM-SessionManagerRunShell`）と、この開催の DCV・SSH のポート転送と SSH セッションのドキュメントだけ |
| `ssm:TerminateSession`・`ssm:ResumeSession` | セッション ID が `{{ATTENDEE_ID}}-` で始まるもの、またはセッションの開始者のタグ `aws:ssmmessages:session-id` が自分の `aws:userid` で始まるもの |
| 参照（`ec2:DescribeInstances`、`ssm:DescribeInstanceInformation`、`ssm:DescribeSessions`、`ssm:GetConnectionStatus`） | すべて（リソースで絞れない操作のため） |

ポート転送のドキュメントは接続先のポートを固定しているため、受講者はインスタンス上の任意のポートへは転送できません。
受講者用ツールの SSH は、既定のシェルのセッションで自分の EC2 の `ubuntu` の `authorized_keys` に期限付きの公開鍵を登録・削除し、SSH セッションのドキュメントのセッションで通信を中継します。
そのため SSH に使う権限は、自分の EC2 への既定のシェルと SSH セッションのドキュメントでの `ssm:StartSession` と、自分のセッションの `ssm:TerminateSession` だけです。

払出し専用ユーザーは、`credentials send --ec2` のために、この開催のタグのインスタンスへの既定のシェルのセッションと、自分のセッションの終了・再開を持ちます。
講師用ロールは、この開催のタグのインスタンスへのシェルのセッション（`ssm:SessionDocumentAccessCheck` 付き）と、`AWS-RunRemoteScript` による Run Command を持ちます。

### ガードレール

受講者ロールには、許可の管理ポリシーとは別に、拒否だけのガードレールの管理ポリシーを付けます。

| 拒否 | 理由 |
| --- | --- |
| `ec2:CreateTags`、`ec2:DeleteTags` | 接続の権限の条件に使うタグを書き換えて、他の受講者のインスタンスに入ることを防ぐ |
| `ec2:ModifyInstanceAttribute`、`ec2:TerminateInstances`、`ec2:RunInstances` | インスタンスの変更・削除・起動を防ぐ |
| `iam:*`、`sts:*` | 権限の変更と、別のロールの引き受けを防ぐ |
| `shared/` への書き込み | 教材とデータセットの改ざんを防ぐ（バケットポリシーと二重にする） |
| `aws:RequestedRegion` が講習会のリージョン以外のすべての操作 | 他のリージョンでの操作を防ぐ |

### 講師用ロールの権限

| 操作 | 範囲 |
| --- | --- |
| `ssm:SendCommand` | ドキュメント `AWS-RunRemoteScript` と、この開催のタグのインスタンス |
| コマンドの結果・インベントリの参照、`ec2:DescribeInstances`・`DescribeVolumes`・`DescribeSnapshots` | すべて |
| `ssm:StartSession` | この開催のタグのインスタンスと既定のシェル |
| `ec2:CreateSnapshot(s)` | この開催のタグのボリューム・インスタンスから、この開催のタグを付けるスナップショットだけ。作成時のタグ付けを許可する |
| `ec2:DeleteSnapshot` | この開催のタグのスナップショット |
| S3 | バケットの一覧、全オブジェクトの読み取り、`shared/` への書き込み・削除 |
| `iam:GetRolePolicy`・`PutRolePolicy`・`DeleteRolePolicy` | 受講者ロール（失効のインラインポリシーの操作） |

### インスタンスロールの権限

- AWS 管理ポリシー `AmazonSSMManagedInstanceCore`
- `shared/` の一覧と読み取り
- `dcv-license.{{REGION}}` のバケットの読み取り（Amazon DCV の EC2 上のライセンス確認）

## 受講者のAWSコンソール利用と資料ビルド

受講者コンソール制御の実装参照は `GClueDev/ai-learning-handson-aws-infra` の `feature/20261008_docs_updates`、コミット `e1415f2b1daf5ad503e69a97698c9282b3f1903a` です。過去の接続実測の出典とは別に、開催YAML契約・IAM拒否・払い出し前確認・配布フラグを照合しています。実AWSでの適用は本資料作成時に未実施です。

開催YAMLの `aws.handson.attendee_console_access` が唯一の正本です。`true` / `false` を真偽値として記載し、引用符付き文字列・数値・nullは使いません。キーの省略は従来互換のtrueです。資料のフォーム・共通JSON・環境変数でこの真偽値を上書きしません。

```yaml
aws:
  handson:
    attendee_console_access: false
```

上記は既存の開催YAMLへ追加するキーの抜粋です。開催ID・アカウント・リージョン・受講者一覧など、インフラに必要な他の設定は既存の正本に残します。

falseの場合、受講者向けのコンソールURL生成・ブラウザでのAWS直接操作・S3コンソールリンクと、そのURLの配布案内を資料に含めません。CLIでのS3保存・回収、SSM、SSH、DCVは継続します。講師・構築担当者自身によるAMI・CloudFormation・S3撤去などの管理コンソール手順は残します。

### falseへの切替と確認の順序

1. インフラと資料が使う同じ開催YAMLをfalseに変更します。
2. アカウントまたは組織でAWS Sign-Inのconsole authorizationが有効か、管理者が読み取り操作で確認します。このアカウント全体の設定はCDKが自動変更する対象ではありません。
3. 通常の構築・変更手順でCDK deployを行います。false対応版では受講者・インスタンスの両ロールに `signin:Authenticate`、`signin:AuthorizeOAuth2Access`、`signin:CreateOAuth2Token` のDenyが必要です。講師ロールは維持します。
4. 実AWSで両ロールへのIAM適用を確認します。false対応版の資格情報払い出しではSign-In設定と配備済みDenyの確認が必要です。確認に失敗した場合は払い出しを進めません。
5. 確認後に資格情報を払い出し、同じYAMLを指定して資料を再ビルドします。配布環境にもfalseが含まれる対応版のツールを使用します。
6. 担当者ページの「このビルドで有効・無効な手順」でYAML名・SHA-256・audience・boolを確認し、開催用資料を配布します。

資料だけをfalseにすることや、ローカルのコンソールURL生成を止めることは、AWS側の拒否を適用した証明にはなりません。console authorizationの有効化が必要で、IAM適用も別に確認します。[AWS Sign-In公式仕様](https://docs.aws.amazon.com/signin/latest/userguide/console-access-control.html)を参照してください。この資料の生成時にAWS操作は行いません。

### AWS側の読み取り確認

管理者の運用環境で、正本YAMLの対象アカウントID・リージョン・プロファイルを指定します。以下は設定照会だけで、有効化は行いません。

```bash
aws signin get-console-authorization-configuration \
  --target-id '<対象アカウントID>' \
  --region '<対象リージョン>' --profile '<管理者プロファイル>'
```

対象アカウントの `consoleAuthorizationEnabled` がtrueと判定できることを確認します。未対応SDK・読取権限不足・設定無効では先へ進めません。組織側の管理も使っている場合は管理者へ適用範囲を確認します。false対応版の払い出し前確認は、対象アカウントの照会に加え、両ロールに添付された管理ポリシーの既定バージョンで、3つのSign-Inアクションに無条件・全リソースのDenyが適用済みかを読み取ります。これは資料ビルドとは別の確認です。

### 開催YAMLを指定してビルドする

実行場所はこのドキュメントリポジトリです。`<開催YAMLの絶対パス>` は、CDK deployで使った正本のパスへ置き換えます。

```bash
export LEROBOT_HANDSON_CONFIG='<開催YAMLの絶対パス>'
python -m mkdocs build -f mkdocs.aws-staff.yml --strict
```

`LEROBOT_HANDSON_CONFIG` は入力YAMLの選択だけを行います。真偽値の指定欄ではありません。YAMLを明示した場合、ファイル不存在・不正な名前空間・不正な型・重複キーはビルドエラーになります。YAMLの値変更は再ビルド後に反映されます。serveでは正本YAMLも監視します。
