## 必要な IAM 権限

### diff・deploy・destroy

構築用 CDK アプリは `CliCredentialsStackSynthesizer` を使うため、CloudFormation はサービスロールではなく実行者の認証情報でリソースを作成・削除します（[インフラ構成の仕様](<<= guide_link('staff/environment/specs/infrastructure.md') =>>)）。
そのため、実行者には CloudFormation の操作に加えて、スタックが扱う各リソースの操作の権限が必要です。
`network.availability_zones` を省略した場合は、synth の時点で Availability Zone の一覧を取得するため、synth にも AWS の認証情報と `ec2:DescribeAvailabilityZones` が必要です。

| サービス | アクション |
| --- | --- |
| CloudFormation | `cloudformation:DescribeStacks`、`cloudformation:DescribeStackEvents`、`cloudformation:DescribeStackResources`、`cloudformation:GetTemplate`、`cloudformation:GetTemplateSummary`、`cloudformation:CreateChangeSet`、`cloudformation:DescribeChangeSet`、`cloudformation:ExecuteChangeSet`、`cloudformation:DeleteChangeSet`、`cloudformation:DeleteStack` |
| CDK のブートストラップ | `ssm:GetParameter`（`/cdk-bootstrap/hnb659fds/version`）、`s3:GetObject`・`s3:PutObject`・`s3:ListBucket`・`s3:GetBucketLocation`（`cdk-hnb659fds-assets-<アカウント>-{{REGION}}`） |
| S3（講習会用バケット） | `s3:CreateBucket`、`s3:GetBucketLocation`、`s3:PutBucketPolicy`、`s3:GetBucketPolicy`、`s3:DeleteBucketPolicy`、`s3:PutBucketVersioning`、`s3:PutEncryptionConfiguration`、`s3:PutBucketPublicAccessBlock`、`s3:PutBucketOwnershipControls`、`s3:PutLifecycleConfiguration`、`s3:PutBucketTagging` |
| IAM（ロール・管理ポリシー・インスタンスプロファイル） | `iam:CreateRole`、`iam:DeleteRole`、`iam:GetRole`、`iam:UpdateRole`、`iam:UpdateAssumeRolePolicy`、`iam:TagRole`、`iam:UntagRole`、`iam:AttachRolePolicy`、`iam:DetachRolePolicy`、`iam:ListAttachedRolePolicies`、`iam:ListRolePolicies`、`iam:CreatePolicy`、`iam:DeletePolicy`、`iam:GetPolicy`、`iam:GetPolicyVersion`、`iam:CreatePolicyVersion`、`iam:DeletePolicyVersion`、`iam:ListPolicyVersions`、`iam:CreateInstanceProfile`、`iam:DeleteInstanceProfile`、`iam:GetInstanceProfile`、`iam:AddRoleToInstanceProfile`、`iam:RemoveRoleFromInstanceProfile` |
| IAM（インラインポリシー） | `iam:PutRolePolicy`、`iam:GetRolePolicy`、`iam:DeleteRolePolicy`（カスタムリソースの Lambda のロールのポリシーと、削除時の受講者ロールの失効のインラインポリシー） |
| IAM（ロールの受け渡し） | `iam:PassRole`（インスタンスロールを EC2 へ、カスタムリソースの Lambda のロールを Lambda へ渡す） |
| IAM（払出し専用ユーザーとアクセスキー） | `iam:CreateUser`、`iam:DeleteUser`、`iam:GetUser`、`iam:TagUser`、`iam:UntagUser`、`iam:AttachUserPolicy`、`iam:DetachUserPolicy`、`iam:ListAttachedUserPolicies`、`iam:CreateAccessKey`、`iam:DeleteAccessKey`、`iam:UpdateAccessKey`、`iam:ListAccessKeys` |
| Lambda（アクセスキーを SSM パラメータに書くカスタムリソース） | `lambda:CreateFunction`、`lambda:DeleteFunction`、`lambda:GetFunction`、`lambda:UpdateFunctionCode`、`lambda:UpdateFunctionConfiguration`、`lambda:InvokeFunction`、`lambda:TagResource`、`lambda:UntagResource` |
| EC2（VPC・subnet・ルートテーブル・インターネットゲートウェイ・VPC エンドポイント） | `ec2:CreateVpc`、`ec2:DeleteVpc`、`ec2:DescribeVpcs`、`ec2:ModifyVpcAttribute`、`ec2:DescribeVpcAttribute`、`ec2:CreateSubnet`、`ec2:DeleteSubnet`、`ec2:DescribeSubnets`、`ec2:ModifySubnetAttribute`、`ec2:CreateRouteTable`、`ec2:DeleteRouteTable`、`ec2:DescribeRouteTables`、`ec2:AssociateRouteTable`、`ec2:DisassociateRouteTable`、`ec2:CreateRoute`、`ec2:DeleteRoute`、`ec2:CreateInternetGateway`、`ec2:DeleteInternetGateway`、`ec2:AttachInternetGateway`、`ec2:DetachInternetGateway`、`ec2:DescribeInternetGateways`、`ec2:CreateVpcEndpoint`、`ec2:DeleteVpcEndpoints`、`ec2:ModifyVpcEndpoint`、`ec2:DescribeVpcEndpoints`、`ec2:DescribePrefixLists`、`ec2:DescribeAvailabilityZones` |
| EC2（インスタンス・セキュリティグループ） | `ec2:RunInstances`、`ec2:TerminateInstances`、`ec2:StopInstances`、`ec2:StartInstances`、`ec2:DescribeInstances`、`ec2:DescribeInstanceAttribute`、`ec2:ModifyInstanceAttribute`、`ec2:CreateTags`、`ec2:DeleteTags`、`ec2:DescribeImages`、`ec2:DescribeVolumes`、`ec2:DescribeNetworkInterfaces`、`ec2:CreateSecurityGroup`、`ec2:DeleteSecurityGroup`、`ec2:DescribeSecurityGroups`、`ec2:AuthorizeSecurityGroupIngress`、`ec2:RevokeSecurityGroupIngress`、`ec2:AuthorizeSecurityGroupEgress`、`ec2:RevokeSecurityGroupEgress` |
| SSM（接続経路のドキュメント） | `ssm:CreateDocument`、`ssm:UpdateDocument`、`ssm:UpdateDocumentDefaultVersion`、`ssm:DeleteDocument`、`ssm:DescribeDocument`、`ssm:GetDocument`、`ssm:AddTagsToResource`、`ssm:RemoveTagsFromResource`、`ssm:ListTagsForResource` |

- SSM パラメータの書き込みと削除はカスタムリソースの Lambda のロールが行うため、実行者に `ssm:PutParameter`・`ssm:DeleteParameter` は要りません。
- ルート EBS の暗号化にカスタマー管理の KMS キーを既定のキーとして設定しているアカウントでは、そのキーに対する `kms:CreateGrant`、`kms:GenerateDataKeyWithoutPlaintext`、`kms:Decrypt`、`kms:DescribeKey` も必要です。
- CloudFormation のリソースの処理が、この表にない参照の操作を求めることがあります。権限の不足で失敗した場合は、スタックのイベントに表示された操作を加えます。

### 管理者の作業

| 作業 | アクション |
| --- | --- |
| アカウントの確認 | `sts:GetCallerIdentity` |
| vCPU・VPC のクォータの確認 | `servicequotas:GetServiceQuota`、`ec2:DescribeInstanceTypes`、`ec2:DescribeInstances`、`ec2:DescribeVpcs` |
| AMI ID とルートデバイス名の確認 | `ssm:GetParameter`（`/aws/service/deeplearning/*`）、`ec2:DescribeImages` |
| 導入済みの AMI の作成（任意） | `ec2:DescribeSubnets`、`ec2:DescribeImages`、`ec2:RunInstances`、`ec2:CreateTags`、`iam:PassRole`（一時的なインスタンスのインスタンスプロファイルのロール）、`ec2:DescribeInstances`、`ec2:DescribeInstanceStatus`、`ssm:DescribeInstanceInformation`、`ssm:StartSession`、`ssm:TerminateSession`、`ec2:StopInstances`、`ec2:CreateImage`、`ec2:TerminateInstances` |
| Availability Zone ごとのインスタンスタイプの提供状況の確認 | `ec2:DescribeInstanceTypeOfferings`、`ec2:DescribeAvailabilityZones` |
| 払出し専用ユーザーのアクセスキーのパラメータの確認 | `ssm:DescribeParameters` |
| 講師に与える KMS キーの確認 | `kms:DescribeKey` |
| インスタンスの中身の確認（任意） | `ssm:StartSession`、`ssm:TerminateSession` |
| 開催中の変更・撤去時の終了保護の解除 | `ec2:ModifyInstanceAttribute`、`ec2:DescribeInstanceAttribute` |
| 撤去時のバケットの片付け | `s3:ListBucket`、`s3:ListBucketVersions`、`s3:DeleteObject`、`s3:DeleteObjectVersion`、`s3:DeleteBucket` |
| 撤去時のロググループの片付け（任意） | `logs:DescribeLogGroups`、`logs:DeleteLogGroup` |
| 使わなくなった導入済みの AMI の削除（開催の撤去とは別の保守の作業） | `ec2:DescribeImages`、`ec2:DescribeInstances`、`ec2:DeregisterImage`、`ec2:DeleteSnapshot` |

導入済みの AMI の作成に使う一時的なインスタンスには、AWS 管理ポリシー `AmazonSSMManagedInstanceCore` を付けたロールのインスタンスプロファイルが必要です。スタックのインスタンスプロファイルはスタックより前に作れないため、管理者が別に用意します。
導入済みの AMI とそのスナップショットには、開催 ID のタグ `handson-deployment` を付けず、AMI 専用のタグ `gclue-ai-handson-ami` を付けます。
導入済みの AMI は複数の開催で使い回すのに対し、講師用ロールは、そのリージョンでタグ `handson-deployment` が自分の開催 ID と一致するスナップショットすべてに `ec2:DeleteSnapshot` を許可されているためです（一斉配布のタグの有無は条件になく、絞り込みは `rollout cleanup-snapshots` の側だけで行います）。
開催のタグを付けると、開催ごとの後片付けの対象と区別できず、共有の AMI とそのスナップショットがある開催の撤去で消されるおそれがあります（登録中の AMI のスナップショットは AWS が削除を拒みます）。
CDK のブートストラップ、クォータの引き上げ申請、Marketplace の購読、講師の権限セットの編集に必要な権限は、それぞれの AWS のサービスの文書に従います。

### 講師

講習会の運用（払出し、失効、教材の公開、一斉配布）に使う権限は、スタックが作る払出し専用ユーザーと講師用ロールに含まれています。
講師自身の認証情報に必要なのは、次の 2 つだけです（`AdministratorAccess` には含まれています）。

| アクション | リソース |
| --- | --- |
| `ssm:GetParameter` | `arn:aws:ssm:{{REGION}}:{{ACCOUNT_ID}}:parameter/GClueAiHandsOn/{{EVENT_ID}}/IssuerAccessKey` |
| `kms:Decrypt` | AWS 管理キー `aws/ssm` |

### 受講者

受講者は、払い出された受講者ロールの一時認証情報だけを使います。
受講者の機器に AWS の長期の認証情報は要りません。
