## 変更するときの注意

- 名前・タグのキー・S3 の構成を変えるときは `contract.py` を変え、構築用と運用ツールの両方のテストを通します。名前を変えると既存のスタックではリソースが置き換わるため、開催中のスタックには適用しません。
- Construct の ID（特に受講者ごとの `Workstation-{{ATTENDEE_ID}}`）を変えると、CloudFormation の論理 ID が変わってリソースが置き換わります。
- インスタンスのプロパティを変えるときは、CloudFormation の更新の規則（置き換え・停止を伴うか）を確かめ、上の表と [講習会用 AWS 環境の構築と撤去](<<= guide_link('staff/environment/procedures/environment.md') =>>) の開催中の変更の表を合わせて更新します。
- ユーザーデータは起動のたびに実行される部分（`bootcmd`）と初回だけの部分（`runcmd`）があります。変更は既存のインスタンスの停止と起動を伴い、初回だけの部分は既存のインスタンスでは実行されません。
- NAT ゲートウェイやインターフェイス型 VPC エンドポイントを加えると、開催ごとに時間課金が増えます。
- 実際のアカウントで差分を確かめるときは `diff` を使い、`deploy`・`destroy` はユーザーの明示的な指示なしに実行しません。テンプレートの検査は `uv run pytest src/handson_cdk` で、AWS に接続せずに行えます。
