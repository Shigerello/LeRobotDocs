## 動作

### ネットワーク

- VPC は開催ごとに 1 つ作り、`vpc_cidr`（/16〜/24、既定 `10.80.0.0/16`）から Availability Zone ごとに /24 の public subnet を 1 つずつ切り出します。
- NAT ゲートウェイとインターフェイス型 VPC エンドポイントは作りません。
- S3 の Gateway 型 VPC エンドポイントを public subnet のルートテーブルに関連付け、同じリージョンの S3 との転送をこのエンドポイント経由にします。
- subnet の `MapPublicIpOnLaunch` は無効にし、パブリック IP はインスタンスごとに明示して付けます。
- 既定のセキュリティグループの規則を消すカスタムリソースは作りません（`restrict_default_security_group=False`）。既定のセキュリティグループはどのインスタンスにも付けません。

### EC2

- 受講者 ID ごとに 1 台を、public subnet に置きます。`instance.availability_zone` の指定があればその Availability Zone の subnet に、なければ先頭の public subnet に置きます。
- パブリック IP を付けます。これは SSM エージェントが AWS のサービスのエンドポイントへ接続するためだけのものです。
- セキュリティグループは受信の規則を持たず、送信はすべて許可します。接続はすべて SSM Session Manager 経由です（接続経路の仕様（元インフラリポジトリの参照資料））。
- IMDSv2 を必須にし、PUT 応答のホップ数の上限を 1 にします。
- 終了保護（`DisableApiTermination`）を有効にします。
- ルート EBS は `root_device_name` のデバイスとして、`root_volume_size_gb` の gp3 を暗号化して作り、インスタンスの終了で削除します。暗号化のキーは、アカウントの EBS の既定のキーです。
- ユーザーデータ（cloud-config）は、初回起動時のパッケージの更新・アップグレード・再起動を行わず、起動のたびに apt の自動更新のユニットを停止・マスクし、初回起動時に `/opt/handson` を `ubuntu` ユーザーの所有で作ります。教材と講義用ツールの配置は、起動後に講師が一斉配布で行います（教材の版と一斉配布の仕様（元インフラリポジトリの参照資料））。

### バケット

- SSE-S3 による暗号化、バージョニング、パブリックアクセスの全面ブロック、オブジェクト所有者の強制（ACL 無効）、TLS 以外の拒否を有効にします。
- 完了しなかったマルチパートアップロードは 7 日で破棄します。
- `RemovalPolicy.RETAIN` で、スタックを削除してもバケットを残します。
- バケットポリシーで、`shared/` への書き込みを講師用ロール以外に拒否します（[アクセス制御の仕様](<<= guide_link('staff/environment/specs/access-control.md') =>>)）。

### AMI

AMI は設定の `instance.ami_id` を、そのリージョンの汎用 Linux の AMI として使います（`MachineImage.generic_linux`）。
AMI を検索・解決する処理は持たず、どの AMI を使うかは設定で固定します。

AMI に求める条件は次のとおりです。

| 条件 | 理由 |
| --- | --- |
| アーキテクチャがインスタンスタイプと合い、その GPU のドライバーが入っていること | GPU を使う講義のため。推奨は AWS Deep Learning AMI（Ubuntu、x86_64） |
| Ubuntu で、`ubuntu` ユーザーがあること | ユーザーデータ、一斉配布、SSH の接続先の OS ユーザーが `ubuntu` に固定されているため |
| SSM エージェントが動くこと | 接続と一斉配布をすべて Session Manager と Run Command で行うため |
| 受講者が SSH・git で接続する講習会では、sshd が 22 番で待ち受け、ed25519 のホスト鍵（`/etc/ssh/ssh_host_ed25519_key.pub`）があること | 受講者用ツールの `ssh`・`git`・`ssh-config` は、SSM のセッションで EC2 の中の sshd へ中継し、ホスト鍵をそのファイルから受け取って照合するため |
| 同じく、`git`、`flock`（util-linux）、GNU の `date` があること | 接続ごとの公開鍵の登録と削除をロックの中で行い、期限を接続先の時刻で求めるため。`git` は git push・pull に使う。Ubuntu のサーバー向けのイメージには通常含まれる |
| 同じく、Session Manager のセッションのユーザー（既定の `ssm-user`）から `sudo -n -u ubuntu` できること | 公開鍵の登録と削除を、シェルのセッションから `ubuntu` に切り替えて行うため。SSM エージェントが作る `ssm-user` は既定でパスワードなしの sudo を持つ |
| DCV で接続する講習会では、Amazon DCV サーバーが入っていて `dcv_port` で待ち受けること | Deep Learning AMI には DCV サーバーが含まれない。インスタンスロールは EC2 上の DCV のライセンス確認に使う AWS のバケットを読める |
| ルートのスナップショットが `root_volume_size_gb` 以下であること | ルートの EBS はスナップショットより小さくできない |
| Marketplace の製品なら、アカウントで購読済みであること | 購読していないと起動できない |

`root_device_name` は AMI の `RootDeviceName` と一致させる必要があります。
一致しないと、指定したサイズの EBS がルートではなく追加のボリュームとして付き、ルートは AMI の既定のサイズのままになります。
CDK もスタックも AMI の情報を読まないため、この不一致は deploy で検出されません。

この教材の再現対象は Ubuntu 24.04 / x86_64 です。対象リージョンで利用可能な AMI は管理者が選定します。Ubuntu 22.04 は同梱の導入スクリプトの対象外です。
スタックはこのパラメータを参照せず、設定に書いた ID を使います。パラメータの値は AMI の更新で変わるため、参照すると更新のたびに deploy でインスタンスが置き換わるからです。

#### ソフトウェアを導入済みの AMI

講義に使う大きなソフトウェア（PyTorch、LeRobot とその依存など）は、元の AMI にそれを入れた AMI を講習会の前に用意し、`instance.ami_id` に指定することを推奨します。
一斉配布は `/opt/handson/` と管理対象のリンクだけを扱いパッケージの導入はしないため（教材の版と一斉配布の仕様（元インフラリポジトリの参照資料））、また受講者ごとに起動後に入れると時間と転送量が台数分かかるためです。

- 導入済みの AMI は開催に属しません。同じアカウント・リージョンの複数の開催で使い回し、寿命は開催と独立しています。一方、EC2 とバケットは受講者のデータが別の開催に漏れないよう、開催と 1 対 1 に保ちます。
- 導入済みの AMI は、構築担当が [手順書](<<= guide_link('staff/environment/procedures/environment.md') =>>) の「（任意）ソフトウェアを導入済みの AMI を用意する」に沿って、使える既存の AMI がない場合だけ、スタックの外の一時的なインスタンスから AWS CLI で手動で作ります。
- 導入済みの AMI には受講者のデータを入れません。元の AMI から起動した一時的なインスタンスだけから作り、受講者が使った講習会のインスタンスからは作りません。AMI を作る前に、作業中の認証情報、コマンドの履歴、パッケージの一時ファイルを消します。
- 名前は `GClueAiHandsOn-AMI-<用途>-<YYYYMMDD>`（`<用途>` は入れるソフトウェアを表す英小文字の短い語。例: `lerobot`）とし、AMI とそのスナップショットにタグ `gclue-ai-handson-ami`（値は AMI の名前）を付けます。手作業の命名の約束で、スタックと運用ツールはこの名前とタグを扱いません。
- 開催 ID のタグ `handson-deployment` は付けません。講師用ロールはこのタグがその開催 ID のスナップショットを削除でき、開催ごとの後片付けの対象と区別できなくなるためです（[アクセス制御の仕様](<<= guide_link('staff/environment/specs/access-control.md') =>>) の「管理者の作業」）。
- AMI の作成は GPU のインスタンスと長い時間を要し、入れるソフトウェアは講義ごとに選ぶため、スタックと運用ツールでは自動化しません。LeRobot のソフトウェア導入は、次の独立したシェルスクリプトで行います。
- 導入済みの AMI も、上の表の条件をすべて満たす必要があります。特に、ルートのスナップショットの大きさは作成時のルートのボリュームの大きさになるため、`root_volume_size_gb` 以下にします。
- 元の AMI が Marketplace の製品なら、製品コードが引き継がれ、購読が引き続き必要です。
- AMI とそのスナップショットはスタックの外で作るため、スタックの削除では消えず、保存している間は料金がかかります。開催の撤去では扱わず、どの開催の設定からも参照されず、その AMI から起動したインスタンスも残っていないことを確かめてから、構築担当が保守の作業として登録を解除し、スナップショットを削除します。

#### EC2 のソフトウェア導入スクリプト {#ec2-のソフトウェア導入スクリプト}

[`scripts/setup-lerobot-ec2.sh`](<<= guide_link('staff/environment/scripts/setup-lerobot-ec2.sh') =>>) は、Ubuntu 24.04・x86_64 上で `ubuntu` ユーザーが実行する LeRobot の導入スクリプトです。GPU ドライバー、SSM、sshd、DCV は元の AMI が提供する前提で、スクリプトはそれらを導入しません。実行にはパッケージ取得先へのインターネット接続と OS の `sudo` 権限が必要で、AWS リソースを操作する IAM 権限や AWS 認証情報は使いません。

| 対象 | 導入内容・場所 |
| --- | --- |
| OS パッケージ | `git`、`git-lfs`、`curl`、`unzip`、`less`、`groff`、`ffmpeg`、`python3.12-venv` を Ubuntu の apt リポジトリから導入する。版は apt に従う |
| uv | 0.12.23 を公式インストーラーで `~/.local/bin` に導入する。その場所に異なる版がある場合は停止する。インストーラーの標準動作に従いシェルの設定へ PATH を追加する |
| AWS CLI | 2.37.10 の公式 x86_64 ZIP を使い、`/usr/local/aws-cli` と `/usr/local/bin/aws` に導入する。同じ版なら再導入せず、異なる版がある場合は停止する |
| LeRobot | v0.6.0 のコミット `30da8e687a6dfc617fcd94afc367ac7071c376ce` を既定で `~/lerobot` に配置する。既存の作業ツリーは同じコミットかつ追跡対象のファイルに変更がない場合だけ再利用する。未追跡のデータセットなどは許容する |
| Python 依存 | LeRobot の公式 `uv.lock` に従い、Python 3.12 と `training`・`dataset_viz` の extra を `uv sync --locked` で導入する |

`--lerobot-dir` で LeRobot の配置先を変えられます。`--check-gpu` は PyTorch の CUDA 利用可否を確認し、`--cache-resnet18` は ACT が使う torchvision の ResNet18 の重みを `ubuntu` ユーザーのキャッシュへ事前取得します。モデルのキャッシュは `~/.cache/torch/hub/checkpoints/` に置かれ、手順書の pip キャッシュ削除では消えません。`--terminal-font` は DCV 内の GNOME Terminal の既定プロファイルに `Monospace 12` とセル間隔 1.00 を設定するための任意オプションです。

スクリプトは EC2 の起動・停止、AMI 作成、認証情報の払出し、教材配布を行いません。導入手順は [構築の手順 2.4.3](<<= guide_link('staff/environment/procedures/environment.md#243-ソフトウェアを入れる') =>>) に記載します。

### Availability Zone

Availability Zone の決め方は、設定によって 2 通りあります（`network.py`（元インフラリポジトリの参照資料）、`config.py`（元インフラリポジトリの参照資料））。

| 設定 | 動作 |
| --- | --- |
| `network.availability_zones` を指定 | その Availability Zone に subnet を作る。AWS への問い合わせはしない。`instance.availability_zone` はこの中から選ぶ（設定の読み込みで検証する） |
| `network.availability_zones` を省略 | synth の時点で `cdk` CLI がアカウントの Availability Zone を問い合わせ、先頭から `max_azs` 個（既定 2）を使う |

- `availability_zones` と `max_azs` は同時に指定できません。設定の読み込みで止めます。
- 指定した Availability Zone は、すべて講習会のリージョンのものである必要があります。
- 省略した場合の問い合わせの結果は `src/handson_cdk/cdk.context.json` にキャッシュされます。アカウント固有の値を含むため、Git の管理対象外です。結果を取り直すには、このファイルを削除します。
- 省略した場合、最初の synth では問い合わせの前のダミー値で組み立てるため、`instance.availability_zone` が VPC に含まれるかは問い合わせの後でしか判定できません。そこで例外ではなく Construct のエラーとして記録し、`cdk` CLI が問い合わせの後の synth でエラーを報告して止まるようにしています。
- 省略した場合は、synth にも AWS の認証情報と `ec2:DescribeAvailabilityZones` が必要です。
