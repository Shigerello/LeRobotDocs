## 制約・既知の限界

### 変更による置き換え・停止

設定を変えて deploy し直したときの影響は次のとおりです。
EC2 は CloudFormation の `AWS::EC2::Instance` の更新の規則に従います。

| 変更 | 影響 | 理由 |
| --- | --- | --- |
| `instance.ami_id` | 全インスタンスの置き換え | `ImageId` の変更は置き換えになる |
| `instance.root_device_name`、`instance.root_volume_size_gb` | 全インスタンスの置き換え | `BlockDeviceMappings` の変更は置き換えになる |
| `instance.availability_zone` | 全インスタンスの置き換え | 置き先の subnet（`SubnetId`）が変わる |
| `network.vpc_cidr`、`network.availability_zones`、`network.max_azs` | VPC・subnet・セキュリティグループ・全インスタンスの置き換え | VPC の CIDR や subnet の構成の変更は置き換えになり、従属するものも置き換わる |
| `attendees` から外す | そのインスタンスの削除 | 受講者 ID ごとの Construct がなくなる |
| `attendees` に加える | そのインスタンスの追加と、受講者ロールの信頼ポリシーの更新 | 信頼ポリシーは一覧にある受講者 ID のセッションタグだけを受け付ける |
| `instance.instance_type` | 全インスタンスの停止と起動 | EBS ボリュームから起動するインスタンスのタイプの変更は、停止を伴う更新になる |
| ユーザーデータ（構築用のコードの変更） | 全インスタンスの停止と起動 | `user_data_causes_replacement` を指定していないため、置き換えではなく停止を伴う更新になる |
| `max_session_duration_seconds` | 受講者ロールと講師用ロールの最大セッション時間の更新 | 発行済みの一時認証情報には影響しない |
| `issuer.access_key_serial` | アクセスキーの置き換えと SSM パラメータの上書き | [アクセス制御の仕様](<<= guide_link('staff/environment/specs/access-control.md') =>>) |
| `deployment_id`、`account`、`region` | 別のスタックとして新しく作られる | スタック名と環境が開催 ID・アカウント・リージョンで決まる |

- 置き換えと削除は終了保護で失敗するため、対象のインスタンスの終了保護を事前に外します。置き換え後のインスタンスには、再び終了保護が付きます。
- 置き換え後のインスタンスは AMI の状態から始まるため、教材の一斉配布（初回の環境構築）をやり直す必要があります。受講者のホームディレクトリの内容も失われます。

### その他

- `vpc_cidr` は、Availability Zone の数だけ /24 の subnet を切り出せる大きさが必要です。/24 の VPC では Availability Zone を 1 つにする必要があります。
- 1 つの public subnet に全受講者のインスタンスを置くため、1 つの Availability Zone の在庫に依存します。在庫は deploy で起動するまで分かりません。
- 開催 ID を変えずに撤去と構築をやり直すと、残っているバケットと名前が衝突して deploy が失敗します。バケットを削除するか、別の開催 ID にします。
- 初回の deploy が失敗してスタックが `ROLLBACK_COMPLETE` になった場合は、削除してから deploy し直します。
- IMDS のホップ数が 1 のため、インスタンス上のブリッジネットワークのコンテナからはインスタンスの認証情報を取得できません。
- 既定のセキュリティグループには、AWS の既定の規則が残ります。

### 撤去で残るもの

スタックの削除（`gclue-ai-handson-cdk destroy`）で、VPC、subnet、S3 の Gateway 型 VPC エンドポイント、セキュリティグループ、EC2 とルート EBS、IAM のロール・ポリシー・インスタンスプロファイル、払出し専用ユーザーとアクセスキー、SSM のパラメータ（カスタムリソースの削除の処理で消す）とドキュメントは削除されます。
次のものは残ります。

| 残るもの | 扱い |
| --- | --- |
| 講習会用バケットとその中身（全バージョン） | `RETAIN` のため。全バージョンと削除マーカーを消してから手動で削除する。バケットポリシーは CDK の既定の削除ポリシーでスタックと一緒に消えるため、撤去後は管理者が `shared/` も削除できる |
| 一斉配布で作った EBS スナップショット | スタックの外で作るため。講師が `rollout cleanup-snapshots` で消す |
| 構築担当が作った導入済みの AMI とそのスナップショット | スタックの外で手動で作り、複数の開催で使い回すため、開催の撤去では扱わない。どの開催でも使わなくなったら、構築担当が保守の作業として AMI の登録を解除してからスナップショットを削除する |
| カスタムリソースの Lambda が作る CloudWatch Logs のロググループ | Lambda が実行時に自動で作るため。値はログに残さない設定にしている |
| ブートストラップのバケットにアップロードしたテンプレートとアセット | ブートストラップの資源のため、講習会の撤去では扱わない |
