## 設計上の判断と理由

| 判断 | 理由 |
| --- | --- |
| 開催ごとに専用の VPC を作る | 他の開催・他の用途のネットワークと分け、撤去でまとめて消せるようにする。CIDR を開催ごとに選べる |
| public subnet だけにし、NAT ゲートウェイを作らない | 受信を一切許可しないため、private subnet に置く利点が小さい。NAT ゲートウェイの時間課金とデータ処理料金をなくす |
| インターフェイス型 VPC エンドポイントを作らない | SSM などのエンドポイントへはパブリック IP で到達できるため。エンドポイントごと・Availability Zone ごとの時間課金をなくす |
| S3 の Gateway 型 VPC エンドポイントを作る | データセットやモデルの重みの転送を AWS のネットワーク内に留める。Gateway 型は料金がかからない |
| パブリック IP を付け、受信を許可しない | SSM エージェントの送信だけでよく、SSH などのポートを開けない。パブリック IPv4 アドレスの時間課金はインスタンスごとにかかる |
| IMDSv2 必須、ホップ数 1 | インスタンスの認証情報を、SSRF やコンテナ内のプロセスから取り出しにくくする |
| 終了保護を付ける | 設定の誤りや手違いの deploy・destroy で、受講者の作業中のインスタンスが消えるのを防ぐ。撤去と置き換えの前には外す手順を必須にする |
| ルート EBS を暗号化し、終了で削除する | 受講者のデータを保存時に暗号化し、撤去で確実に消す。残す成果は S3 に置く運用にする |
| apt の自動更新を止める | 講習会の途中で環境が変わったり、再起動したりするのを防ぐ。更新は講師の一斉配布で行う |
| バケットを残す | 受講者の成果を、スタックの削除で誤って失わないようにする |
| 名前を開催 ID から決める | 開催をまたいだアクセスを IAM の条件とリソースの名前で防ぎ、運用ツールが設定ファイルだけで動けるようにする |
| `CliCredentialsStackSynthesizer` を使う | ブートストラップのロール（デプロイ用・アセットの発行用・問い合わせ用）を使わず、実行者の認証情報だけで deploy・destroy する。実行者の権限の範囲がそのまま作れるものの範囲になり、権限の監査が実行者のポリシーだけで済む |

### `CliCredentialsStackSynthesizer` の影響

- CloudFormation はサービスロールではなく実行者の認証情報で、すべてのリソースを作成・更新・削除します。実行者には CloudFormation の操作に加えて、スタックが扱う各リソースの操作の権限が必要です（[アクセス制御の仕様](<<= guide_link('staff/environment/specs/access-control.md') =>>) の「必要な IAM 権限」）。
- テンプレートとアセット（払出し専用ユーザーのアクセスキーを SSM パラメータに書くカスタムリソースの Lambda のコード）は、ブートストラップで作るバケット `cdk-hnb659fds-assets-{{ACCOUNT_ID}}-{{REGION}}` に実行者の認証情報でアップロードします。そのため、ブートストラップ（既定の修飾子 `hnb659fds`）は必要です。
- deploy の途中で実行者の一時認証情報が切れると、CloudFormation の操作も失敗します。IAM Identity Center のセッションは、deploy の前にログインし直しておくのが安全です。
