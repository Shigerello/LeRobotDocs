## 構成

スタックは次の 5 つの Construct で組み立てます（`app.py`（元インフラリポジトリの参照資料））。
ロールはバケットを、EC2 は VPC とインスタンスプロファイルを参照するため、この順に生成します。

| Construct | 作るもの |
| --- | --- |
| `HandsOnNetwork` | 専用 VPC（public subnet だけ）、インターネットゲートウェイ、S3 の Gateway 型 VPC エンドポイント |
| `HandsOnBucket` | 講習会用バケットとバケットポリシー |
| `AttendeeConnectivity` | 接続先のポートを固定した Session Manager のドキュメント（DCV と SSH のポート転送、SSH セッション） |
| `HandsOnRoles` | 払出し専用ユーザーとそのアクセスキーの SSM パラメータ、受講者・講師・インスタンスのロール |
| `Workstations` | 受信を許可しないセキュリティグループと、受講者ごとの EC2 |

### 名前とタグ

名前とタグのキーは、運用ツールの `gclue_ai_handson.contract`（元インフラリポジトリの参照資料） だけで定義し、構築用もこれを参照します。
名前はすべて開催 ID から決まるため、運用ツールはスタックの出力を読まずに、設定ファイルだけからリソースを特定できます。

| 対象 | 名前 |
| --- | --- |
| スタック（CDK の stack ID を兼ねる） | `GClueAiHandsOn-{{EVENT_ID}}` |
| 物理名・`Name` タグ | `GClueAiHandsOn-{{EVENT_ID}}-{種類}`（例: `-Vpc`、`-PublicSubnet1`、`-S3Endpoint`、`-Workstation-{{ATTENDEE_ID}}`） |
| IAM ロール | `GClueAiHandsOn-{{EVENT_ID}}-Attendee`、`-Instructor`、`-Instance`（インスタンスプロファイルはインスタンスロールと同名） |
| 払出し専用ユーザーとその管理ポリシー | `GClueAiHandsOn-{{EVENT_ID}}-Issuer` |
| セキュリティグループ | `GClueAiHandsOn-{{EVENT_ID}}-Workstation` |
| SSM ドキュメント | `GClueAiHandsOn-{{EVENT_ID}}-DcvPortForward`、`-SshPortForward`、`-SshSession` |
| SSM パラメータ | `/GClueAiHandsOn/{{EVENT_ID}}/IssuerAccessKey` |
| バケット | `gclue-ai-handson-{{EVENT_ID}}-{{ACCOUNT_ID}}-{{REGION}}`（63 文字以内） |

スタック内のすべてのリソースに、開催 ID のタグ `handson-deployment` を付けます（コスト配分タグにも使えます）。
受講者の EC2 には、さらに受講者 ID のタグ `attendee` を付け、作成時にボリュームへも伝播させます。
この 2 つのタグは IAM の条件に使うため、受講者ロールではタグの変更を拒否しています（[アクセス制御の仕様](<<= guide_link('staff/environment/specs/access-control.md') =>>)）。
